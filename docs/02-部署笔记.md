## 3. 日常使用

```bash
# 启动仿真（一条命令，内部包含所有环境变量）
bash /home/justin/TJ-Superpower/deploy/run_sim.sh

# 另开终端：起飞 + 悬停 + 降落
source /opt/ros/humble/setup.bash
source /home/justin/TJ-Superpower/ros_gz_ws/install/setup.bash
source /home/justin/TJ-Superpower/sp_nav_drone_27/install/setup.bash
ros2 run offboard_controller offboard_controller_node --ros-args \
  --params-file /home/justin/TJ-Superpower/sp_nav_drone_27/install/offboard_controller/share/offboard_controller/config/offboard_controller.yaml \
  -p use_sim_time:=true &
ros2 topic pub --once /offboard/command std_msgs/msg/String "{data: start_builtin}"
ros2 topic pub --once /offboard/command std_msgs/msg/String "{data: hold}"   # 悬停
ros2 topic pub --once /offboard/command std_msgs/msg/String "{data: land}"   # 降落

# 验收
bash /home/justin/TJ-Superpower/deploy/verify_a.sh
```

控制器命令全集：`start_builtin`（内置航线）、`start_external`（外部路径）、`hold`、`land`、`stop`。

## 4. 关键改动清单（按重要性）

### 4.1 ros_gz 必须源码重编（最关键的环境问题）
apt 的 `ros-humble-ros-gz-bridge 0.244.26` 依赖 **`libignition-transport11` / `libignition-msgs8`（Gazebo Fortress）**，而 PX4 v1.16.2 用 **Harmonic（gz-transport13 / gz-msgs10）**。两者能互相发现话题，但消息解不出来，表现为桥接疯狂打印 `Unknown message type [8]/[9]` 且 ROS 侧一条数据都收不到。
→ 用 `ros_gz 1.0.25`（Harmonic 线）源码构建到 `ros_gz_ws`，启动时**先 source 它**以覆盖 apt 版本。配套做了三处本地适配：
- `gz_aliases/`：提供 `gz-transport` / `gz-msgs` 的 CMake 别名（系统只有 `gz-transport13` / `gz-msgs10`）；
- 删除 `marine_acoustic_msgs`（未安装的水下声学消息）相关的 mappings、convert 源与头文件；
- `yaml-cpp::yaml-cpp` → `yaml-cpp`；`rclcpp::BestAvailableQoS()` → best-effort QoS（Humble 无此 API）。

### 4.2 ORB 同步队列 30 → 3（最隐蔽的问题）
`sp27_flight.launch.py` 里 `sync_queue_size: 30`，在 15 Hz 下等于缓存 ~2 秒图像，ORB 输出因此**固定比仿真时钟落后 0.75 s**；而 `vio_bridge` 的陈旧阈值是 **0.3 s**，于是每一帧都被静默丢弃（`return std::nullopt`，连警告都很少），表现为"没有视觉位姿 → PX4 不解锁"。
→ 改为 `sync_queue_size: 3`，实测延迟从 **752 ms 降到 50 ms**，视觉位姿恢复 14.9 Hz。

### 4.3 仓库自身缺文件（不是环境问题）
`ORB_SLAM3` 的 CMakeLists 引用了、但仓库没提交的文件：
- `Thirdparty/DBoW2/DUtils/Timestamp.{h,cpp}`
- `Thirdparty/g2o/g2o/stuff/timeutil.{h,cpp}`
→ 从上游 `UZ-SLAMLab/ORB_SLAM3` 取同版本文件补齐。缺失会让 `add_library` 报 `No SOURCES given`。

### 4.4 ORB_SLAM3 示例程序改为可选
46 个 `add_executable` 依赖 `Examples/`、`Examples_old/`（约 600 MB 数据集，稀疏检出未取）。里程碑 A 只需要 `libORB_SLAM3.so`。
→ 在 `CMakeLists.txt` 的 `# Build examples` 处加 `option(SP27_ORB_BUILD_EXAMPLES ... OFF)` 开关；原文件备份为 `CMakeLists.txt.orig`。

### 4.5 PX4 侧的三处本地适配
- **跳过 `gazebo.patch`**：它只修改 `models/x500_depth/model.sdf`（旧对比机型），要打它得拉 500 MB 上游模型库；`sp27_uav` 的模型自洽（只引用 `sp27_uav_base`），资源已由 `export_assets.py --apply` 导出。
- **关掉 uXRCE-DDS 与 gz 光学流插件**：这两个模块的 ExternalProject 会在**编译期**从 GitHub 拉代码（校园网此刻完全不通），而 SP27 用 MAVLink（MAVROS）而非 uXRCE-DDS，机体也没有光流传感器。
  改动：`boards/px4/sitl/default.px4board` 里 `CONFIG_MODULES_UXRCE_DDS_CLIENT=n`；`src/modules/simulation/gz_plugins/CMakeLists.txt` 注释掉 `add_subdirectory(optical_flow)` 及其在 `px4_gz_plugins` 里的依赖。
- **补一个 `worlds/default.sdf`**：PX4 从 `worlds/*.sdf` 生成 `gz_<机型>_<世界>` 目标，缺 `default.sdf` 就没有 `gz_sp27_uav` 目标（launch 会报 `unknown target`）。内容复制自 `sp_27_features.sdf`。

### 4.6 GPS 子模块用 tarball 绕开 git
`make px4_sitl` 会自己 `git submodule update` GPS 驱动，被校园网 TLS 审计中断。→ 从 codeload 下 tarball 解压到 `src/drivers/gps/devices`，放一个 `.git` 占位文件满足 ninja 依赖，并全程 `export GIT_SUBMODULES_ARE_EVIL=1` 跳过子模块检查（PX4 自带的官方开关）。

### 4.7 世界文件暂时去掉 RMUC2027
`sp_27_features.sdf` 里 `include model://RMUC2027`，但该模型的 `meshes/model.dae` 被 `.gitignore` 排除（README 也写了"迁移时需另行准备"）。网格缺失会让 Gazebo **直接拒绝加载整个世界**（`Failed to load a world`）。
→ 已在世界源码里把该 include 注释掉并写明原因与恢复方法。**这是精度不如原作者的主要原因**（少了棋盘格墙这个特征源）。

### 4.7b 查看画面的正确方式（重要）
WSLg 的 Gazebo 窗口走 D3D12 呈现，在**远程桌面（RDP）会话里会呈现为纯黑窗**（窗口存在、数据正常，只是抓不到 GPU 表面）。
判断依据：窗口宿主进程是 `msrdc`，标题带 `[WARN:COPY MODE]`。
→ **请在本机物理屏幕上看仿真画面**，不要通过远程桌面看。
若必须用远程桌面，可给 Gazebo 加软件渲染（`LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe`），
代价是相机帧率从约 15 Hz 掉到约 6.6 Hz。
另一个不依赖 GUI 的验证手段：直接从 `/tidesense/left/image_raw` 抓一帧存 PNG，能证明渲染确实在工作。

### 4.8 其他环境项
- `.wslconfig`：`memory=8GB / processors=24 / swap=4GB`（原文件备份 `.wslconfig.bak-20261106`）。
  **不要再调到 12 GB**：主机只有 15.7 GB，实测仿真满载只占约 3 GB，而 12 GB 的配置会把 Windows 压到
  「可用物理 0.16 GB / 可用提交 0.01 GB」，表现为 DSH、浏览器、远程桌面随机卡死甚至报 `800705af`。
  8 GB 下所有指标满速（图像/ORB/视觉位姿均 14.97 Hz）。
- 校园网 SSL 审计（`Scholar Verify`）根证书导入系统信任库，否则 `git/curl/apt` 走 HTTPS 全部失败。
- MAVROS 需要 GeographicLib geoid；bootstrap 里那条脚本失败了，改用 `GEOGRAPHICLIB_DATA` 指到用户目录，**免 sudo**。
- `rosidl_pycommon` 不在 Humble apt 索引里 → 从 `ros-iron-rosidl-pycommon` 的 deb 里取纯 Python 模块（`apt-get download` 不需要 root）。
- 私有仓库克隆：用 `gh` 的 token 做 `http.extraheader`，并采用 **blobless + 稀疏检出**（只取里程碑 A 需要的目录）把 1.62 GB 压到 181 MB。

## 5. 实测结果

| 指标 | 值 |
|---|---|
| IMU | 249 Hz |
| 左目图像 | 14.9 Hz |
| ORB 里程计 | 15.3 Hz |
| 视觉位姿 → MAVROS | 14.9 Hz |
| ORB 里程计时间戳延迟 | **50 ms**（修复前 752 ms） |
| 起飞高度 | 0.998 m |
| 6 秒悬停漂移 | x −7.7 mm / y +8.2 mm / z +2.6 mm（悬停高度 1.00 m） |
| 3D 位置误差（全程 944 帧） | 均值 0.073 m，RMSE 0.083 m，p95 0.165 m |
| 3D 位置误差（飞行段 854 帧） | 均值 0.076 m，RMSE 0.085 m，p95 0.173 m |
| 姿态误差 | 中位 0.55°，RMSE 0.60°，p95 0.98° |

对比日志：`sp_nav_drone_27/log/orbslam3_flights/flight_*/`（`comparison.csv` 含 `error_3d_m`、`attitude_error_deg`，可直接做 B 阶段统计）。

> 原作者报告悬停 RMSE 4.6–5.7 cm、旋转段 14.5 cm。在修正内存压力（§4.8）与同步队列（§4.2）后，
> 我们的飞行段 RMSE 8.5 cm、全程 8.3 cm、中位 6.1 cm，已与原作者同一量级；
> 剩余差距主要来自 §4.7 场地特征缺失（RMUC2027 网格不在仓库里）。

## 6. 已知限制 / 下一步

1. **RMUC2027 场地网格缺失** → 向仓库负责人索取 `external_files/worlds/RMUC2027/meshes/`（约百 MB），放进后把世界里的 include 取消注释即可。
2. **落点上锁高度 0.63 m**：降落指令后已上锁，但位置不在 z≈0，疑似落在围栏/障碍物上。需要确认落点逻辑，或检查 `MPC_LAND_SPEED` 与地形。
3. 未做**完整固定航线**（上升 1 m → 前飞 5 m → 右转一圈 → 返航）的端到端验证 —— 这次一进 `BUILTIN_ROUTE` 就发了 `hold`，属于里程碑 A 范围。B 阶段应让它跑完整条航线并出误差报告。
4. `flight.yaml` 的 `hardware` 段保持空值未动；实机标定、PX4 视觉融合参数、`sensor_launch` 都需要在有硬件后另做。
5. PX4 那三处改动（uXRCE-DDS / optical_flow / default.sdf）是为**没有外网**的这台机器做的取舍；换到能访问 GitHub 的机器上，可以还原成官方做法。

## 7. 换机器复现的最短路径

```bash
# 1) 系统依赖（唯一需要 sudo 的一步）
sudo bash deploy/bootstrap_root.sh

# 2) 代码：仓库用 gh token 稀疏克隆；PX4 拉 v1.16.2 + 关键子模块
git clone --filter=blob:none --no-checkout --depth 1 -b dev_wwa_air <repo>
git sparse-checkout init --no-cone   # 只勾 src/sp_nav_bringup、sp_localization、sp_control、sp_robot_msg、sp_filght_sim、sp_communicator、bash
git checkout -f dev_wwa_air
git clone --depth 1 -b v1.16.2 <PX4> src/sp_filght_sim/external_files/PX4-Autopilot

# 3) 补 PX4 补丁与仿真资源
bash deploy/patch_px4.sh

# 4) 构建（Pangolin v0.6 → ORB_SLAM3 → colcon）
bash deploy/build.sh

# 5) 启动与验收
bash deploy/run_sim.sh &
bash deploy/verify_a.sh
```

**顺序上最容易踩的三个点**：ros_gz 必须用 Harmonic 版（§4.1）、`sync_queue_size` 必须调小（§4.2）、`GIT_SUBMODULES_ARE_EVIL=1` 与 `GEOGRAPHICLIB_DATA` 两个环境变量不能漏。
